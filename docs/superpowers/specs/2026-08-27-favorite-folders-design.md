# 收藏夹：搜索 + 文件夹分类

## 目标

1. 收藏夹右上角加搜索，按标题/作者过滤自己收藏的帖子。
2. 收藏的帖子可以归类到自建文件夹（红利、银行、科技……），长按归类。

## 硬约束（决定了整个方案的形状）

- **收藏夹的数据在 NGA 服务端**：`thread.php?favor=1`，分页拉取。本地没有全量列表。
- **NGA 的收藏夹没有文件夹概念**，接口里没有任何可用字段。所以文件夹只能是**纯本地**的标签，不同步、换设备会丢。
- **服务端不支持在收藏夹里按关键词搜**。搜索只能在本地做。
- **长按已经被「删除收藏」占用**（`TopicFavoriteFragment.onLongClick`，进页面还会弹 toast「长按可删除收藏的帖子」）。

结论：需要一份**本地收藏快照**，搜索和文件夹都建立在它之上。

## UI

打开收藏夹（根视图）：

```
┌─ 收藏夹 ───────────────── 🔍 ⋮ ─┐
│  📁 红利   📁 银行   📁 科技      │  ← 文件夹区；一个都没建时整块不占地方
├──────────────────────────────────┤
│  帖子标题 A            作者/回复  │
│  帖子标题 B            作者/回复  │  ← 未分类的帖子，就是现在这个列表
│  帖子标题 C            作者/回复  │
└──────────────────────────────────┘
```

- **归类过的帖子不在根列表出现**，只在对应文件夹里 —— 和文件夹的直觉一致。
- **文件夹区是横向可滚动的一行**，文件夹多了往右滑，不换行、不挤压下方列表的高度。
- **点文件夹就地切换**：文件夹区换成 `← 红利`，下方列表换成该夹的帖子。不开新页面。系统返回键先退回根视图。
- **长按文件夹** → 弹菜单：`重命名` / `删除文件夹`。删夹只是把里面的帖子放回未分类，不删帖子，对话框里要写清楚这点。
- **文件夹内同样能长按帖子**，菜单一样（移到别的夹 / 删除收藏）。
- **长按帖子** → 弹菜单：`移到文件夹` / `删除收藏`。原来长按直接弹删除确认，现在多一步，顺带降低误删。
- **移到文件夹** → 单选对话框：现有文件夹 + `新建文件夹…` + `移出文件夹`。
- **搜索**（右上角 🔍，复用已有的 `menu_search.xml` SearchView）：输入即过滤，**搜全部收藏，无视当前在哪个文件夹**。已分类的结果行尾标一个文件夹名小标签，因为搜的时候通常不记得当初放哪了。
  搜索期间**文件夹区隐藏** —— 结果是跨文件夹的平铺列表，此时留着文件夹区会让人以为搜索被限定在某个夹里。清空关键词后恢复到进入搜索前的视图。
- **溢出菜单加「同步全部收藏」**。

### 布局插入点

`TopicSearchFragment.onCreateView()` 返回 `R.layout.fragment_topic_list`，是可覆写的。
`TopicFavoriteFragment` 覆写它，inflate 新的 `fragment_topic_favorite.xml`：外层竖直容器 = 文件夹区 + 原布局。
**新布局必须保留 `swipe_refresh` / `list` / `loading_view` 三个 id**，否则父类的 ButterKnife 绑定会拿到 null。

## 数据层：`FavoriteStore`

新文件，app 模块。存 `filesDir/favorite_snapshot.json`：

```json
{
  "folders": ["红利", "银行", "科技"],
  "items": {
    "12345678": {
      "subject": "...", "author": "...", "fid": 706, "board": "大时代",
      "replies": 120, "postDate": 1690000000,
      "folder": "红利", "updateTime": 1756300000000
    }
  }
}
```

- `items` 以 tid 字符串为键，upsert 是 O(1)。
- `folders` 单独存且有序，允许空文件夹（先建夹再往里放）。
- `folder` 为空串表示未分类。

**为什么用 JSON 文件而不是 Room**：`AppDatabase` 在 `lib_bu_account`（账号模块），把论坛收藏数据放进去是错的模块边界；且它 `version = 1` + `exportSchema = false`，加表要补迁移。项目本来就到处用 JSON 文件持久化（`board_bookmark.json`、`cache/<tid>/<tid>.json`）。几千条全读进内存约 500KB，搜索是内存过滤，瞬时。

### 接口

```
load() / save()                       // 磁盘 IO 走子线程
upsertFromList(List<ThreadPageInfo>)  // 增量写入，见下
folders(): List<String>
createFolder(name) / renameFolder(old, new) / deleteFolder(name)
setFolder(tid, folderOrEmpty)
itemsIn(folderOrEmpty): List<Item>    // 空串 = 未分类
search(keyword): List<Item>           // 全量，不分文件夹
pruneTo(Set<Int> serverTids)          // 只在「同步全部收藏」结束时调用
```

### upsert 规则（最容易写错的地方）

每加载完一页收藏列表就 `upsertFromList`：

- 已存在的条目：**只刷新 subject/author/fid/board/replies/postDate/updateTime，绝不动 folder**。
  写错这里会让用户的分类在下次下拉刷新时被抹掉。
- 不存在的条目：新增，`folder` 为空（未分类）。
- **不删除任何条目**。日常只加载了前两页，若按当前页结果清理，没加载到的会被全删。

### 删除文件夹

条目不删，`folder` 置空回到未分类。删夹是整理动作，不该连带丢帖子。

## 同步全部收藏

溢出菜单触发，分页拉完整个收藏夹补全快照。

- **500ms 页间隔 + 失败退避 2s/4s/8s、连续 4 次失败中止**，和 `TopicCacheAllTask` 同一套节奏。收藏夹几百页时不限速会触发 NGA 限流（限流表现为连续 302，OkHttp 跟 21 跳后抛 `ProtocolException`，失败一页等于打 21 次请求）。
- **`TopicCacheAllTask` 的下载队列在跑时让路**，反之亦然——两条请求流叠加同样会触发限流。复用 `TopicCacheUpdateTask.setDownloadRunning` 那套让路机制。
- 全部页成功拉完才调 `pruneTo(全集)`，清理在网页端已取消收藏的孤儿条目。**中途失败就不 prune**，否则会误删没拉到的部分。

## 错误处理

- 快照文件损坏/解析失败 → 当作空库重建，不崩。日常加载会重新填回来。
- 磁盘写失败 → 记日志 + toast，不影响列表浏览（快照是增强，不是主数据源）。
- 搜索无结果 → 列表区显示「没有匹配的收藏」，不是空白。
- 帖子全部归类完导致根列表为空 → 显示「所有收藏都已分类，点上方文件夹查看」，避免看起来像收藏丢了。
- 打开一个空文件夹 → 显示「这个文件夹还没有帖子」。
- 文件夹重名 → 建夹时校验，提示「已存在同名文件夹」。
- 文件夹名为空或全空格 → 拒绝，提示。

## 测试

`FavoriteStore` 是纯逻辑（除 IO 外），app 模块已有 JUnit（`CacheUpdateQueueTest`、`PriceGapTest`）。要覆盖：

1. upsert 已有条目时 folder 不被覆盖 ← 核心回归用例
2. upsert 不删除未出现在本页的条目
3. `deleteFolder` 后条目回到未分类且不丢失
4. `itemsIn("")` 只返回未分类，不含已分类
5. `search` 跨文件夹返回，并带出所属文件夹
6. `pruneTo` 只删不在服务端全集里的条目
7. 重名/空名建夹被拒
8. `renameFolder` 把夹内所有条目的 folder 一并改掉，不留下指向旧名的孤儿

UI 部分（文件夹区渲染、就地切换、长按菜单）装机手测。

## 不做

- 不同步到 NGA（服务端没有这个概念）
- 文件夹不嵌套
- 一个帖子只属于一个文件夹
- 快照不做导出/导入（要的话另开一件事）
